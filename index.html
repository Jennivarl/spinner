GenLayer Consensus Spinner

Five validators begin on uneven orbits, converge into one cluster, hold for a beat, and scatter into the next round. It is the shape of a GenLayer transaction, used as a loading state.

Pure CSS. No JavaScript, no images, no dependencies. One element, five children, two custom properties.

Why five, and why it loops

A GenLayer round is five validators executing independently before anything is agreed, so the spinner uses five nodes rather than an arbitrary count. They begin on deliberately uneven orbits, because independent execution does not look tidy, and then all five converge at the same instant. Staggering them in time instead would look unsynchronised and never actually converge, so the moment of agreement would never happen.

It never resolves and stops. A transaction that fails consensus rotates its leader and runs the round again, and a spinner that settled once would be telling the wrong story about the thing it is waiting on.

Size and colour are custom properties, so it inherits a theme without touching the stylesheet: 

<div class="gl-spinner"
     style="--gl-spinner-size: 32px; --gl-spinner-color: #fff">

Details that matter in a real UI

Only transform and opacity are animated, so the browser can keep it on the compositor and it does not cause layout work while a page is already busy loading.

It respects prefers-reduced-motion. Rather than freezing, which reads as a hung page, the nodes settle onto the ring and pulse together, so it still says "working" without the orbit.

Every instance carries role="status" and a label, so a screen reader announces the wait instead of silence.
